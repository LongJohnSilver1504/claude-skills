## 1.1.0 (2026-09-30)

### Added

- **`design-review` — `references/runtime-evidence.md` and a step 3, "Open the interface".** The skill already said "no visual finding from source alone when runtime behavior decides it" and gave no mechanism, so in practice every review was static and half the escalation triggers — what clips at 320px, where focus lands, which pair renders on which background — were inference dressed as findings. The reference holds the method: a four-rung ladder (running instance → built preview → existing harness → static only) with an explicit refusal to start servers, install anything or trigger destructive actions; the viewport tiers with what each one catches that no other does; the keyboard, state and console walks; and what separates an observation from a guess. The coverage table gained a leading `runtime` row naming the rung reached, and at `static only` every runtime-decided domain reads `Not verified: no rendered instance` rather than `Clear`. `design-critic` carries read-only Chrome tools to work the ladder. Adapted from the browser-driven review agent in [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (MIT); its severity ladder and report shape were not imported — this plugin already has one.
- **`evals/` — routing cases with an offline gate.** The boundaries between these skills live entirely in their descriptions: nothing but a `NOT for` clause keeps a dark-mode token question out of `accessibility`. Eleven cases, one per skill carrying the clause, each a realistic request plus two deterministic `tool_used` graders — the owning skill fires (`min: 1`), the competitor it names does not (`min: 0, max: 0`). No LLM judge. `npm run eval` runs them from `design-craft/` in ~40s for ~$1.44; `scripts/validate.mjs` gained the free half, failing when a `NOT for` skill has no case or a grader names a skill that does not exist. All eleven passed on first run — a regression gate on descriptions, not a discovery tool. Adapted from the upstream project's relevance-evaluation harness.
- **`design-direction` — a product-type routing table in `references/moods.md`.** Five mood signal lists left too much room: "a booking tool for a spa" and "a booking tool for a freight yard" read the same through them. Thirty-nine product types now route to a mood (or a two-mood pairing, type-and-shape first, palette-and-density second), each row carrying the reflex that lane has to be pulled off — the accent on every heading for premium SaaS, the purple gradient for wellness, the mono body for developer tools. The idea of keying the cold start to product type is adapted from the same upstream project; none of its palette, font-pairing or style data was copied, and the reasoning is in `.out-of-scope/design-preset-catalog.md` in the repo root.

- **`motion` — `references/library-contracts.md`.** The CSS-first ladder took easing, duration and exit as far as CSS goes but never stated the Motion library's own contract, which fails silently: `AnimatePresence` must stay mounted outside the condition, the direct child needs a stable `key` and an `exit` prop, `mode` is `sync`/`wait`/`popLayout` per situation, `initial` must match server-rendered output or hydration mismatches, and `prefers-reduced-motion` has to be branched in code because a media query cannot reach values passed as props. Linked from the skill's interruption-and-exit step. Adapted from the `motion-patterns` and `motion-foundations` skills in Affaan Mustafa's `ecc-universal` collection (MIT); its token, spring-preset and `isLowEnd` device-tier system was deliberately not imported — design-craft extends the project's tokens rather than forking them.

- **`mobile-web` — a ninth reference skill for the phone-browser platform layer.** Nothing owned it: the few mobile rules the plugin had were scattered (a tap-highlight bullet and `touch-action` in accessibility's hit-area reference, `100dvh` in hierarchy-layout's adaptivity recipes) and the rest — `viewport-fit=cover`, without which every `env(safe-area-inset-*)` is `0px`; `svh` for heroes vs `dvh` for shells; root `overscroll-behavior: none` with `contain` on inner scrollers; `interactive-widget=resizes-content` for the Android keyboard; `-webkit-touch-callout` on controls; `theme-color` per scheme; and the fact that DevTools device mode reproduces none of it — was missing entirely. The skill owns those, with a symptom table that names the owner for every symptom it does not own. Wired into `design-review` (third in the order, after hierarchy-layout; `Not reviewed: no phone target` on desktop-only surfaces), `design-help`, the README catalog, the validator's reference-skill list (it carries the canonical Reporting tail) and a routing case (`evals/12-mobile-web`, `accessibility` as the competitor). Adapted from the `mobile-native` skill in Emil Kowalski's collection (MIT), rewritten; of its eleven fixes, seven are owned here, two are split with their owners (tap lag: press feedback stays with ui-polish and motion; long-press: label selectability stays with typography), and two — sticky hover and input zoom — stay with accessibility and typography.
- **Owners took the details `mobile-native` had and they lacked** instead of mobile-web restating them: accessibility's hover gate is now `(hover: hover) and (pointer: fine)` with the Tailwind v4/v3 notes, and its forms list gained `enterkeyhint`, `autocapitalize="none"`/`autocorrect="off"` and `inputmode="decimal"`; typography's input-zoom rule notes iOS never zooms back out on blur, and its `user-select` rule now covers control labels (with the `-webkit-` prefix Safari needs), never `body`. Accessibility's tap-highlight and `touch-action` bullets and hierarchy-layout's `100dvh` line became pointers to mobile-web — the old line put `100dvh` on every full-viewport section, which shifts a marketing hero mid-scroll; heroes take `100svh`. `design-review`'s runtime ladder now says a 375px desktop browser is not a phone, so mobile-web's domain reads `Not verified: no device` without one.
- **`motion` — scout mode is a full read-only workflow (`references/opportunities.md`).** It sweeps ten seams, gates every candidate on frequency, purpose, budget and function, and must list what it rejected — a scout that approves everything over-animates. `design-help` routes "what could be animated here?" to it.
- **`motion` — `references/vocabulary.md`.** Turns a vague description ("the bouncy thing when a popover opens") into the exact term, and each term links to the recipe or value that builds it. `design-help` routes naming questions to it.
- **`motion` — new recipes** for a comparison slider, spring-smoothed pointer tracking and a 3D flip/orbit, plus two stacked-toast edge cases (a hover gap bridge, pausing the timer in a hidden tab). From a gap pass on Emil Kowalski's `emil-design-eng`: 40 rules already covered, 4 adopted, 8 rejected. `scale(0.96)` was kept over the source's `0.97`, and its pointers to easing-curve websites were rejected, so every exact value has a single source. Scout mode and the vocabulary adapt his `find-animation-opportunities` and `animation-vocabulary` (MIT).

### Changed

## 1.0.0 (2026-08-25)

### Added

Initial release: a stand-alone design plugin, separate from the `claude-skills` pipeline, synthesized from the best of seven public skill collections and organized the way Matt Pocock organizes his — a router, a main flow, shaping skills, and a reusable reference layer.

- **Start here** — `design-help` (router).
- **Main flow** — `design-direction` (design read + dials, grounding ladder, anti-default rules, persisted `.design/style-lock.md`, reference study with a similarity dial, redesign protocol), `landing-page` (one offer → one audience → one action, narrative arc, twelve named page shapes rotated against `.design/log.json`, conversion copy, hero tests, asset cast, ship-completeness, and a marketing-tier motion-and-effects reference — GSAP/ScrollTrigger/Lenis tiers by motion dial, word reveals, pinned scroll-scrubbed sequences, sticky stacks, parallax, progress timelines, marquees, island nav, spotlight and magnetic hovers, gradient borders, container lines, framed grids, layered shadows, progressive blur, atmosphere and mesh backgrounds — distilled from Meng To's web-design techniques and elayadesign's motion choreography), `design-review` (evidence not taste, escalation triggers, cheaper-fix ladder, one ranked Before/After/Why table, screen and change scopes with Introduced/Regression/Pre-existing).
- **Shaping** — `variants` (three answers on one named axis behind a picker in the real page), `stress-states` (one component rendered under every reachable scenario; the page is the report).
- **Reference layer** — `hierarchy-layout`, `typography`, `color-system`, `ui-polish`, `motion`, `interface-copy`, `accessibility`, `pick-library`. The seven rule-owning skills share a byte-identical Reporting block so `design-review` can consolidate them.
- **Agent** — `design-critic`, read-only, preloads `design-review`.
- **Validator** — `scripts/validate.mjs` checks frontmatter, the <500-line budget, "Use when" triggers, cross-skill paths, dangling skill names, the canonical Reporting block, read-only agents, and count/version sync.

Sources synthesized (all MIT-licensed): Jakub Krehel's `interfaces` (review architecture, domain skills, variant, break), Emil Kowalski's skills (motion framework, recipes, library picks, Apple fluid-interface principles), codeswithroh's `tastemaker` (style lock, anti-slop gates, narrative arc, page shapes, diversification), ConardLi's `web-design-engineer` (design read and dials, checkpoints, redesign protocol), Meng To's skills (reference-inspired brand worlds with a similarity dial), elayadesign's landing-page and redesign skills (page structure, conversion copy, content realism), and the Refactoring UI principles already condensed in `claude-skills`.
